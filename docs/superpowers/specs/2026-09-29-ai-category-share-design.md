# GameLife：灰区按时间比例盖住整槽

日期：2026-09-29  
状态：已确认，待实现  
范围：灰区的文本判断和截图判断不再点任务。两者返回主线、支线、杂项、娱乐的时间比例。程序把比例换成秒数，加上硬规则已经量到的离开和娱乐，用秒数最多的一类盖住整段已观测时间。产品仍是活动监测器。硬规则和元数据自动结案仍在 AI 之前。

本文覆盖并取代 `2026-09-29-ai-task-match-prompt-design.md` 全文，以及该文所取代的各处里与「必须点中 `task_id`」冲突的句子。上游规格里未被那篇文取代的部分，仍以上游为准。

不改：硬规则顺序、娱乐名单的硬匹配、闲置离开、元数据自动结案阈值、任务标题的本地匹配、提示最多 20 条任务、发币折扣、人工改判、受保护窗口禁止上传、已经写成待复核的槽不重跑。

## 1. 问题

临时做的事往往没有任务 id。要求 API 点中某一条未完成任务时，这些槽会停在待复核。一个 15 分钟槽里也可能混着几类活动。用户接受用时间最多的那一类盖住整槽，少数分钟跟着被算进这一类。

## 2. 成功标准

| 项 | 必须 |
| --- | --- |
| 调用时机 | 硬规则和元数据已经能结案的槽不调用 AI。未定秒数为 0 也不调用 |
| 空任务 | 没有未完成任务，只要还有未定秒数，仍然调用文本；文本不合法时再看截图 |
| 材料 | 提示含未完成任务（可为空）、非空类别说明、非空应用名单、窗口摘要。写明这些只帮助估计四类时间比例。截图另加现有的窗口占用、提示秒数和这一帧的应用、标题、网址、文档路径 |
| 回复 | 只接受 `{"mainline": number, "side": number, "admin": number, "entertainment": number}`。四个数都在 0 到 1，加起来与 1 相差不超过 0.02。不要 `task_id`，不要辅助，不要离开 |
| 不合法 | 缺键、超出范围、加总不对、非数字、JSON 不合法、超时、无密钥、接口失败：该步不结案 |
| 盖槽 | 秒数最多的一类写成整段已观测时间。其余主线 / 支线 / 杂项 / 娱乐 / 离开清零。未观测缺口保持未观测 |
| 平局 | 整数秒相同的几类，按主线、支线、杂项、娱乐、离开取第一个确实并列的。五类都是 0 时不盖槽，维持待复核 |
| 发币 | 主线按已观测秒数原额，计入 8 小时。支线、杂项按已观测秒数走现有折扣，不计入 8 小时。娱乐、离开为 0 |
| 截图 | 文本已经合法结案则不再截图。截图结案时 `used_vision = 1`。没有截图、截图被跳过或错过、或截图受保护：文本未结案则待复核 |
| 旧槽 | 已经 `final` / `unknown` / `pending_review` 的槽不重算 |

明确不算本波的事：不把杂项名单或支线名单改回硬规则；不按概率拆开发币；不重算已结案槽；不从界面去掉历史「辅助」；不改折扣和 20 条上限；不改人工改判。

## 3. 秒数与盖槽

未定秒数 = 已观测秒数 − 硬规则离开秒数 − 硬规则娱乐秒数。小于 0 时当 0。

未定秒数为 0：不调用 API。只比较硬规则离开和硬规则娱乐。

未定秒数大于 0：把四个比例乘未定秒数，四舍五入到整数秒（`.5` 远离 0，与 `f64::round` 相同）。

| 类 | 参与比较的秒数 |
| --- | --- |
| 主线 | `round(mainline × 未定秒数)` |
| 支线 | `round(side × 未定秒数)` |
| 杂项 | `round(admin × 未定秒数)` |
| 娱乐 | 硬规则娱乐秒数 + `round(entertainment × 未定秒数)` |
| 离开 | 硬规则离开秒数 |

比例只描述未定时间，所以娱乐名单已经命中的秒数不会再被乘一次。

取最大秒数的一类。并列时按主线、支线、杂项、娱乐、离开检查，用第一个等于最大秒数的类。5 分钟支线、5 分钟杂项、5 分钟离开：主线是 0，第一个并列的是支线，整槽为支线。8 分钟主线、7 分钟支线：整槽为主线。

盖槽时，获胜类的活动秒数写成这段已观测时间，另外四类写成 0。未观测不改。发币秒数也是这段已观测时间，再沿用现有的 `min(已观测, 槽长, 900)` 上限。因此少数类的分钟会计入获胜类的发币，这是接受的误差。

## 4. 提示与调用

文本和截图共用这一段说明：

> 估计尚未被硬规则定性的窗口时间里，主线、支线、杂项、娱乐各占多少。四个数相加为 1。未完成任务、类别说明和应用名单只是估计依据，不是要返回的任务。离开和已经命中娱乐名单的时间不要放进这四个数。只回复 JSON `{"mainline": number, "side": number, "admin": number, "entertainment": number}`。

正文仍按任务、非空类别说明、非空应用名单、窗口摘要排列。任务仍最多 20 条，挑选顺序不变。本地标题匹配仍用钉住的全集。截图在此之后保留窗口占用、提示秒数和截图帧上下文。

调用顺序：

1. 先 `judge_slot`，不传入截图结果。
2. 未定秒数为 0：用第 3 节在离开和娱乐之间结案。
3. 窗口摘要非空：发送文本。合法则结案，`used_vision = 0`，不再截图。
4. 仍未结案，且有可上传的截图：发送截图。合法则结案，`used_vision = 1`。
5. 否则待复核，不改调用前的活动明细。

摘要为空则跳过文本，有截图仍可走第 4 步。受保护的历史样本不进文本摘要，但不因此禁止一张未受保护的截图。受保护的截图本身仍禁止上传。

## 5. 代码与文案

| 位置 | 改动 |
| --- | --- |
| `crates/gamelife-core/src/task_ai.rs` | 解析四个比例并按第 3 节盖槽。生产结案不再读取 `task_id` |
| `build_task_match_prompt` 的说明 | 改为第 4 节。任务、说明、名单仍写入提示 |
| `compose_vision_prompt` | 使用同一份说明，并保留窗口占用与提示秒数 |
| `src-tauri/src/scheduler.rs` | 有未定秒数就调用，空任务也调用。文本合法则不再截图 |
| `src/pages/Settings.tsx`、`CLAUDE.md`、`AGENTS.md`、`.cursor/rules/specs.mdc` | 判定说明改为多数类盖住整槽。本规格列入索引，并写明它取代 `2026-09-29-ai-task-match-prompt-design.md` |

设置页「判定顺序」改为：

1. 硬规则：锁屏或暂停 → 离开；娱乐名单 → 娱乐；闲置满 3 分钟 → 离开；GameLife → 支线；未完成任务的标题对上 → 按该任务的角色。对不上 → 待定。杂项名单和支线名单不在这一步定性。
2. 元数据够确定就直接结算，不调 AI：匹配到的主线满 13 分钟，且支线、杂项、娱乐合计不超过 1 分钟 → 主线；这三类合计满 5 分钟且压过主线 → 归到占优的一类；离开满 10 分钟且匹配主线不足 5 分钟 → 离开。
3. 剩下的是灰区。没有尚未定性的时间：在已经量到的离开和娱乐里取较长的一类盖住整段已观测时间。有尚未定性的时间：文本判断返回主线、支线、杂项、娱乐的时间比例。任务、类别说明和应用名单只帮助估计，不必对应某条任务。
4. 文本的比例不合法，且这一槽有可用截图：截图判断用同一份回复再估一次。取秒数最多的一类盖住整段已观测时间。整数秒相同时按主线、支线、杂项、娱乐、离开取第一个并列的。没有截图、截图受保护或回复不合法 → 待复核，不猜类别。

类别说明的空值说明保持：「灰字为样稿。空着保存不进提示。写了也只在灰区帮助 AI 估计时间比例，不直接定类别。」

历史槽上的辅助显示保留。新的槽末结算不再产生辅助。

## 6. 测试

- 8 分钟主线、7 分钟支线：整槽主线，发币秒数等于已观测秒数，支线桶为 0。
- 5 分钟支线、5 分钟杂项、5 分钟离开：整槽支线。
- 四个比例加起来不是 1，或缺键：不结案。
- 未定秒数为 0：不调用 API，在离开和娱乐之间取较多者。
- 没有未完成任务但有未定时间：仍然发送文本。
- 文本不合法、截图合法：`used_vision = 1`，且按截图的比例盖槽。
- 已有的硬规则和元数据自动结案测试继续通过。
