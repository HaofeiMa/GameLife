# GameLife E：计划本外壳与任务判定

日期：2026-09-11  
状态：已确认（用户 2026-09-11 审阅通过）  
范围：用可自建列表的计划本取代 Quest；槽末文本 AI + 截图回退；四页中文外壳（今日 / 本周 / 商店 / 设置）。删除时间轴页。

产品仍是科研主线时间校验器，不是完整 GTD。外壳学 TickTick 的每日清单 + 一日日历，商店学礼品卡墙。不拷贝 TickTick / Habitica 的源码或资源。

本文覆盖并取代：

- `2026-09-10-gamelife-design.md` 中 Quest 输入与「今日 / 时间轴 / 本周 / 商店 / 设置」的**呈现**（采样、缺口、账本幂等、Gold Day、连胜公式仍以该文为准）。
- `2026-09-11-today-mainline-design.md` 的 Quest 契约（证据词、hero、最多 3 条）。新槽不再钉 `quest_version_id` 当判定依据。
- `2026-09-11-game-feel-design.md` 中「不预置货架」：本波允许在空商店写入一次示例礼品；兑换事务、娱乐倒计时、无系统通知仍有效。
- 判定匹配从「evidence 子串」改为「当天已排期任务 + 窗口元数据 → 文本 AI，认不出再视觉」。`2026-09-11-judgment-grounded-core-design.md` 的硬规则（离开、娱乐、永不截屏、落地自动 Core 的 *观测* 条件）仍先于 AI 执行；自动 Core 不再依赖 Quest 关键词。

未提及的行为仍以 2026-09-10、Wave 1、观测引擎、落地判定为准。

## 1. 问题

今日页是三张 Quest 卡片加英文标签，时间轴是槽列表，本周是一张表，商店是表单行。使用者要的是：

- 界面以中文为主，待办底 + 游戏徽章
- 可自建列表的任务（主线 / 支线 / 长期 / 杂项），自然语言加任务
- 一天两列日历：计划 | 实际识别
- 本周多面板；商店方形礼品卡；设置分基础 / API / 名单

Quest 证据词既难填也容易误伤。判定改为当天任务标题 + 窗口信息交给 AI。

## 2. 成功标准

| 项 | 必须 |
| --- | --- |
| 导航 | 今日、本周、商店、设置。无时间轴页 |
| 中文 | 按钮、徽章、toast、托盘、类别名均为中文。应用名、路径、API 地址保持原样 |
| 能量 | 界面不再出现 XP / 经验，一律称「能量」。账本字段仍可叫 `xp_delta` |
| 列表 | 可自建。预置主线、支线、长期、杂项。同时只能一个主线列表 |
| 加任务 | 顶部输入用规则解析中文日期/时段/`#列表`，不为此打 AI |
| 今日 | 左栏：徽章 + 输入 + 按列表分组的今日任务。右栏：独立日历面板，默认 1 天两列（计划 \| 实际），可翻日期 |
| 复核 | 点今日右栏「实际」块：待复核可分类；已终结只能报告误判 |
| 本周 | 三个成品面板：按类别、按天、高效时段。实现须超过线框质量 |
| 商店 | 小方形礼品卡；硬币清单与能量清单分开；空店预置示例；底部兑换记录 |
| 判定 | 槽结束至多一次文本 AI；不够再用本槽已有截图。JSON 失败 → 待复核，不发币 |
| 发币 | 主线不打折且计入 8h/宝箱/连胜；支线 6 折；杂项 3 折；长期默认不判定，若排到具体时段则 6 折。非主线不计入 8h/连胜 |

明确不算失败：关窗错过 toast；自然语言漏解析时整句进当前列表；没配 API 时任务能加、槽进待复核。

## 3. 不变量

1. 15 秒采样；缺口不外推；进程死亡是未观测，不是离开。`credited ≤ observed ≤ 实际槽长`。
2. 一天最多 96 个 15 分钟槽。周末不采样。
3. 永不截屏：不截图、不把该窗口标题/路径送进模型、该段不发币。内置项不可删。
4. 账本 `UNIQUE reward_event_key`。已 `final` 的槽不改经济。报告误判只留记录。
5. Gold Day（当天主线 credited ≥ 28800）之后不再产生硬币或能量。已有余额可继续兑换。
6. 主线 tick 仍是每 900 秒 credited → 1 硬币、每 90 秒 → 1 能量，每日上限不变。打折用更长的秒数门槛，不出现小数硬币。
7. 商店单事务；同一 `redemption_id` 不双扣；同时最多一段未结束的能量娱乐会话。
8. 无系统通知、不申请通知权限、无音效。Habitica GPL 资源不用。
9. `document_path` 不得从窗口标题伪造。
10. 改 `src-tauri/` 后 `cargo test --offline -p gamelife` 必须编译并跑过。前端 `npx vitest run --dir src`。
11. 测试禁止 `std::env::set_var("HOME", …)`。
12. 不引入子任务、重复规则、云同步、协作、一条任务多个时段、全天无钟点任务（长期的周/月范围除外）。

## 4. 导航与视觉

左侧窄图标栏：今日、本周、商店、设置。主区浅底。窗口加宽以并排清单和日历。

徽章（今日左栏顶部与商店顶栏共用语言）：

- 硬币：今日新增 · 总数
- 能量：今日获得
- 连胜：圆环中的数字

颜色：主线绿、支线蓝、长期紫、杂项橙、娱乐红、离开/未观测灰。列表、日历块、本周图同一套。

中文对照：Coins→硬币，XP/经验→能量，Chest→宝箱，Gold Day→黄金日，Core→主线，Support→辅助，Side→支线，Admin→杂项，Distraction→娱乐，Away→离开，Unobserved→未观测，pending review→待复核，Trusted→信任应用，Never Capture→永不截屏，Early start→早开始，Streak→连胜。界面不出现 Quest。

## 5. 列表与任务

### 5.1 列表

```
TaskList { id, name, sort, role: mainline | side | longterm | chore | custom }
```

- `mainline` 全额；任意时刻恰好一个（预置「主线任务」，不可在未改派前删除）。
- `side` 6 折；预置「支线任务」。
- `longterm` 6 折且默认不判定；预置「长期计划」。
- `chore` 3 折；预置「杂项」。
- `custom` 按 6 折（自己的额外列表，与支线同档）。

可重命名、排序、自建。自建默认 `custom`。

### 5.2 任务

```
Task {
  id, list_id, title,
  done: bool,
  start: DateTime?, end: DateTime?,   // 有则按时段对齐 15 分钟，最短 15 分钟
  range: WeekOrMonth?                 // 仅长期：本周 / 本月，无具体日
}
```

勾完只表示计划完成，不发币。一条任务第一版只占一个时段。

**进入当天判定集合**（最多 20 条，超出须先勾完或改期）：

- 未完成，且 `[start, end)` 与当天相交
- 所属列表不是长期，**或者**长期但被排到了具体时段

未排期的长期只出现在列表里，不点亮计划列、不进 AI。

槽开始时钉死一份快照（任务 id、标题、列表 role）。改任务只影响尚未开始的槽。历史槽不改写。已有 `quest_versions` 行保留备查，新槽不再读取 Quest 做匹配。升级**不**把旧 Quest 自动变成任务，需自己用输入框重加。无当天可判定任务 → 主线 credited = 0（与无 Quest 相同）。

### 5.3 自然语言输入

规则解析，不打模型。例：

`明天上午十点到十一点，RAIDS+会议讨论 #杂项`

→ 明天 10:00–11:00，标题「RAIDS+会议讨论」，列表杂项。

支持：今天/明天/后天、周几、上午下午晚上、点/点半、`#主线` `#支线` `#长期` `#杂项` 及自建列表名。无 `#`：加入当前正在看的列表；在「今日」汇总则默认主线。失败：整句当标题，进当前列表，不排期，可再点开改。

## 6. 判定与发币

槽结束，不每 15 秒打 AI。

```
硬规则（先）
  锁屏/暂停 → 离开
  娱乐规则 / D2 → 娱乐，不发币
  GameLife 自身 → 记为系统「支线」类别且不发币（不是使用者支线任务的 6 折）
  缺口 → 未观测
  永不截屏窗口 → 不上传、不送模型、不发币

否则文本 AI（一次）
  输入：本槽快照里的判定集合 + 本槽样本的 app/title/url/document_path/idle 摘要
  输出 JSON：task_id | null, confidence
  合法且 confidence ≥ 0.7 且 task_id 落在本槽快照内 → 按该任务列表发币，类别映射见下
  否则 → 本槽已有截图走现有视觉；再失败 → 待复核，credited 0
```

JSON 不合法、超时、未配密钥：待复核，不发币。

类别映射：主线→主线；支线/长期/自建→支线；杂项→杂项；硬规则的娱乐/离开/未观测不变。

发币（命中且观测秒数计入折扣基）：

| 来源 | 硬币 / 能量 | 8h、宝箱、连胜 |
| --- | --- | --- |
| 主线任务 | 不打折（900s→1 硬币，90s→1 能量） | 计入（`credited_core`） |
| 支线 / 自建 / 已排期长期 | 6 折（1500s→1 硬币，150s→1 能量） | 不计入 |
| 杂项 | 3 折（3000s→1 硬币，300s→1 能量） | 不计入 |

折扣秒累计用独立账本键（如 `validated_side_coin:<date>:<n>`），与主线 `validated_coin` 分开，避免打乱每日 32 主线硬币上限。非主线硬币/能量另计，不受那 32/320 上限约束，但 Gold Day 之后同样停发。送进 AI 的摘要含 idle；空闲与观测缺口优先，不发币。勾选任务不发币。

## 7. 今日页

左栏一块面板：

- 标题「今日」
- 硬币、能量、连胜
- 自然语言输入
- 当天任务按列表分组（主线 / 支线 / 长期 / 杂项 / 自建）

右栏另一块面板：

- 标题「YYYY年M月D日 周X」
- **只提供 1 天两列**（不做 3 天，避免计划/实际变成六列）；‹ 今天 › 翻日期
- 两列：计划 | 实际。计划来自该日时段任务；实际来自槽判定，15 分钟一块
- 当前槽在实际列描边并写「正在识别」
- 现在时刻红线
- 未来日实际列为空；历史日显示已判定结果

左栏始终是**日历日为今天**的任务与徽章，不随右栏翻到的日期改写成昨天的清单。右栏可浏览其他日期的计划/实际。

点实际块打开详情：待复核给出主线/辅助/支线/杂项/娱乐/离开；已终结仅「报告误判」。未观测不能点成离开。权限条、娱乐倒计时、结束今天、连胜冻结仍在今日页（冻结可收在次级区域，不进设置）。

## 8. 本周页

三个子面板，实现须做成成品图（图例、留白、空状态、数字标注），不得停留在线框条。

1. **按类别**：主线 / 支线 / 杂项 / 娱乐 / 离开 / 未观测 / 待复核，对 `activity_seconds` 跨槽求和后显示整数分钟。
2. **按天**：工作日堆叠柱（主线/支线/杂项）。周末不采样，空或极矮。
3. **高效时段**：本周每个钟点主线秒 / 该小时观测秒的热力。用于回答「通常什么时间效率高」。

未排期长期不进统计。标题显示本周日期范围与主线合计。

## 9. 商店页

顶栏：硬币余额、今日能量。进行中的能量兑换在顶栏或能量卡上显示剩余时间。

两块清单：

- **硬币兑换**：无时长。空店预置：一杯奶茶 32、一顿外卖 64、一本新书 48。
- **能量兑换**：有时长（≥5 分钟）。空店预置：B 站 45 分钟、游戏 30 分钟、短视频 15 分钟。同时只能一段。

礼品为**小方形卡**（一排约 5–6 张），渐变底 + 图标或首字 + 名称 + 价格。末张「+」添加。示例仅在愿望表为空时写入一次，可改名/改价/停用。

**兑换记录**：时间、商品、类型（硬币 / 能量）、扣币、能量行状态（进行中 / 已结束）。只读，不可撤单。

解锁：与现网相同，整天商店一把锁：当天 `SUM(credited_core) ≥ 3600` 之前两栏都不能兑。

## 10. 设置页

三个板块（页内分段或标签）：

1. **基础设置**：开机启动、截图保留、样本保留天数。无采样间隔。
2. **API 设置**：文本判定与视觉回退的提供方、地址、模型、密钥（钥匙串）。可测连通。
3. **名单设置**：信任应用、永不截屏（内置只读）、娱乐规则、阅读应用、支线规则。

文案中文。Chrome URL 自动化权限说明保留：拒绝则 URL 为空，不阻断采样。

## 11. 模块与数据流

```
今日输入 → tasks / task_lists（SQLite）
槽开始 → 钉 task_snapshot_json（取代新槽的 quest 匹配）
槽结束 → 硬规则 → 文本 AI →（可选）视觉 → JudgeOutput
       → resolve_slot（主线 credited_core + 可选折扣账本键）

get_today → 今日任务、槽、徽章、娱乐、冻结
get_week  → 类别合计、按天、按小时热力
商店      → wishes / redemptions / entertainment_sessions（现有）+ 空店种子
```

纯函数放 `gamelife-core`：列表/任务规范化、自然语言解析、折扣 tick 键、快照校验、AI JSON 校验。I/O、HTTP、钥匙串仍在 `src-tauri`。前端只通过 `src/lib/api.ts` 调命令。

删除或停用今日页 Quest 编辑、时间轴页组件与「时间轴」导航。

## 12. 错误处理

| 情况 | 行为 |
| --- | --- |
| 解析失败 | 整句标题、不排期 |
| 当天判定任务 >20 | 保存或加任务时拒绝并提示 |
| 无主线列表 | 禁止，必须先指定 |
| AI/视觉失败 | 待复核，0 币 |
| 永不截屏 | 不请求、不发币 |
| 兑换失败 | 错误码回 UI，不扣款 |
| 商店锁定 | 卡片不可兑，说明差多少主线分钟 |

## 13. 测试要点

- 自然语言：示例句、无 `#`、失败回退、15 分钟对齐
- 判定集合：长期无时段不进；排期后进；勾完不进
- 快照：改任务不影响已开始槽
- 折扣 tick：15 分钟主线 1 币 10 能量；25 分钟支线 1 币；50 分钟杂项 1 币；不计入 8h
- AI JSON 非法 / 无密钥 → pending_review
- 永不截屏不调用模型
- 空商店种子只插入一次；兑换记录只读
- 前端无 Quest、无时间轴路由；类别与 toast 中文
- 现有缺口、unobserved、账本幂等、Gold Day 回归仍绿

## 14. 实现顺序（计划阶段再拆任务）

1. core：列表/任务/解析/快照/折扣键；DB 迁移  
2. 槽钉快照 + 文本 AI + 视觉回退接线；停用 Quest 匹配  
3. 设计系统与中文；今日页（含复核）  
4. 本周三面板（成品级）  
5. 商店礼品卡 + 种子 + 记录  
6. 设置三板块；删除时间轴  

线框只定结构。今日双列、本周图、商店卡在实现时按成品视觉做，不得以示意 HTML 的粗糙度为准。
