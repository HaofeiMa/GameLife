## 1. 问题

任务页第一版能用，但列表对齐、右键、改期、排序都不顺手；日历不能拉时长；今日计划列和列表能力不一致；计划钟点还在卡判定，跟「观测到在做哪条未完成主线就算主线」不符。重复若预先展开会占满日历。需要一版交互补完，并把判定从「当天已排期集合」改成「未完成任务匹配」。

## 2. 成功标准

| 项 | 必须 |
| --- | --- |
| 列表 | 复选框与分组色点左对齐，勾选色 = 该组角色色。无「排序」按钮。组内与跨组可拖顺序 |
| 右键 | 列表块、日历块、今日计划块同一份菜单：更改日期、移动到 ▸、创建副本、放弃 |
| 复制 | 菜单「创建副本」；选中后 ⌘C / ⌘V（也认 Control） |
| 改期 | 开始/结束各一行（日期 + 15 分钟时刻），准时、重复，底栏清除 / 确定。功能参考系统日历，视觉走本 App 存档风 |
| 重复 | 无 / 每天 / 每周 / 每月。同时只显示一条未完成；勾完成才生成下一次 |
| 提醒 | 设置总开关默认关。开后可多选准时及开始前 5/15/30/60 分钟，到点系统横幅 |
| 日历 | 拖块改位；拖上下边改时长；列右缘活动竖条（有槽数据才画） |
| 今日 | 计划列同样右键、拖位、拉边、复制；仍不在今日新建任务、不改组名 |
| 判定 | 未完成任务（四角色、不论日期与是否排期）都可匹配。计划时段不是门槛。锁屏/离开/娱乐仍优先。对不上则 AI |
| 全天 | 不做 |

明确不算失败：关窗错过 toast；没配文本/视觉 API 时对不上的槽待复核；系统拒绝通知权限时开关可开但弹不出；Windows / Linux 通知接到同一接口但本波不保证真机效果。

## 3. 不变量

1. 15 秒采样；缺口不外推；进程死亡是未观测。`credited ≤ observed ≤ 实际槽长`。
2. 一天 96 个槽。周末不采样，但周末可以排期。
3. **观测优先于计划**。娱乐硬规则命中就是娱乐、0 币，即使某条未完成主线标题对得上。
4. 勾选完成、放弃、改期、复制、排序都不发币。
5. 账本 `UNIQUE reward_event_key`。已 `final` 的槽不改经济。已开始的槽 `task_snapshot_json` 仍 `COALESCE` 钉死。
6. 给 AI 的快照最多 20 条。本地 token 匹配用全部未完成任务。不再因「当天已排期 ≥ 20」拒绝写入。
7. 不引入 FullCalendar、dnd-kit、Radix、子任务、一条任务多个时段、全天条。不引入应用内音效。
8. 界面中文。能量称「能量」。颜色只来自 `--cat-*` / `theme.ts`。改期面板也不写死 hex、不模仿 iOS 灰白控件。
9. 页面只经 `src/lib/api.ts` 调 `invoke()`。
10. 改 `src-tauri/` 后 `cargo test --offline -p gamelife` 必须跑过；改 core 跑 `gamelife-core`；改 `src/` 跑 `npx vitest run --dir src`。
11. 测试禁止 `std::env::set_var("HOME", …)`。
12. 不删 `ticktick_cache` 空表。`user_version` **升到 4**（只为任务新列）。
13. GameLife 自己的窗口仍是支线，不因标题匹配给自己发满额主线。

## 4. 分层

```
任务页 / 今日计划列
  列表拖动 · 共用右键 · 改期面板 · 日历缩放 · 活动竖条

设置
  任务通知总开关

判定
  钉未完成快照 → 硬规则 → 任务匹配 → 灰区文本 AI / 视觉
```

计划钟点只服务日历和提醒，不服务「能不能算主线」。

## 5. 数据

`task_lists` 不变。`tasks` 增加：

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `sort` | INTEGER NOT NULL DEFAULT 0 | 组内顺序；越小越靠上 |
| `repeat` | TEXT NOT NULL DEFAULT `'none'` | `none` / `daily` / `weekly` / `monthly` |
| `remind_json` | TEXT NOT NULL DEFAULT `'[]'` | JSON 数组，元素只能是 `0, 5, 15, 30, 60`（开始前多少分钟；`0` = 准时） |

`range` 仍保留、本波 UI 不露。不做 series 表：下一次是新 `id` 的一行。

`config.json` 增加 `task_notifications: bool`，默认 `false`。不进 `secrets.json`。

备份：新列随 `tasks` 走现有快照；`merged.db` 仍不合并任务表。

## 6. 列表与右键

分组行：折叠箭头、角色色点、组名、未完成数。

任务行：复选框**与色点左对齐**（不要与箭头齐），`accent-color` 为该组角色色。其后标题、时段或「未排期」。

页头「排序」删除。组内顺序只来自 `sort`。`···` 仍负责添加分组、显示/隐藏已完成。3/7 天切换不变。

拖动（指针捕获，同现有日历，禁止 dnd-kit）：

- 组内上下：重写该组 `sort`。
- 拖到另一组：改 `list_id` 并插入该位置。
- 已完成在「显示已完成」时也可拖。
- 自然语言回车新建：`repeat='none'`，`remind_json='[]'`，`sort` 接到目标组最大值之后。

右键（三处同一组件）：

1. 更改日期…
2. 移动到 ▸（其它分组，不含当前组）
3. 创建副本
4. 放弃任务（确认后 DELETE；不生成下一次）

创建副本与粘贴：新 UUID，抄标题、`list_id`、时段、`repeat`、`remind_json`，`done=false`，`sort` 接到目标组末尾。剪贴板只在本进程内有效（内部 MIME / JSON），不是系统日历事件。

## 7. 改期、重复、提醒

### 7.1 面板

本 App 的 `Dialog`：开始一行（日期控件 + 时刻下拉）、结束一行（日期可与开始不同 + 时刻下拉）、准时、重复、底栏「清除」「确定」。无全天、无时区（本机本地）。时刻步进 **15 分钟**。最短 15 分钟。

- **确定**：写入 `start`/`end`（`align_range`）。
- **清除**：`start`/`end` 置空，`repeat='none'`，`remind_json='[]'`。行还在，变未排期。
- 未排期打开面板：开始/结束给当天默认块（现在起向下取整 15 分钟，时长 30 分钟），确定才写入；取消不写。

### 7.2 重复

仅已排期可设非 `none`。未排期保存时若带了重复，拒绝并 toast。

勾完成：`done=true`，然后若 `repeat ≠ none` 且原 `start`/`end` 齐全，**同一事务**插入下一条：

- 新 id；标题、分组、`repeat`、`remind_json` 照抄；`done=false`。
- 时段：按规则把原 `start`/`end` 平移一个周期，保持时长。
- 若平移后开始仍早于**今天 0 点**，继续加周期直到开始 ≥ 今天 0 点。只插一条。
- 每月：日号对不上时落到目标月最后一天（1 月 31 日 → 2 月最后一天）。
- 每周：同一星期几，+7 日。
- 新行 `sort` 接在该组未完成末尾。

放弃、清除时段：不生成下一次。同时界面上只有一条未完成实例，故改期不必问「仅此一次 / 从此以后」。

取消勾选：只把这一行 `done=false`，**不收回**已经插入的下一次。若因此出现两条相似的未完成，由使用者放弃或再完成。

### 7.3 提醒

设置页开关「任务通知」，绑定 `task_notifications`。默认关。打开时申请系统通知权限；关掉则取消已登记的任务通知。

每条任务可多选偏移。只给**当前这条**未完成已排期实例登记。完成、放弃、改期、关开关：取消旧的，按新状态重排。无应用内声音。

macOS 用系统横幅（关窗在托盘也可出现）。Windows / Linux 接同一命令接口，本波不保证真机。

## 8. 日历与今日计划列

对齐 15 分钟。未排期拖进日历：落点起 **30 分钟**（已有）。已排期拖块：时长不变，改开始。

上下边缘约 6px：上边改开始、结束不动；下边改结束、开始不动。最短 15 分钟，不能拖穿。中间区域仍是移动。

活动竖条：每列右缘一条窄轨，96 格对应 96 槽，颜色 `--cat-*`（主线 / 支线 / 杂项 / 娱乐 / 离开 / 未观测 / 待复核）。数据复用 `get_day_view` 的 slots（`dominant` + `pending`）。有数据才着色，没有就空。只读，不参与拖放。周末、未来、尚未采样的今天后半，空着。

今日计划列：同一右键、同一拖位、同一拉边、同一复制。换到其它自然日仍走改期面板或任务页。今日不提供新建输入、不改分组名；「移动到」可以改分组。

## 9. 判定

### 9.1 钉快照

槽开始：所有 `done=false` 的任务（四角色，含未排期、含排在别的日子的）进入候选。`TaskSnapshot { id, title, role }` 形状不变。

本地匹配用全集。写入 AI 提示的快照 ≤ 20：先放本槽样本 haystack 能 token 命中的，再补主线，再按列表 `sort` + 任务 `sort` 补齐。不要钉 `[]` 来表示「太多」。

已开始的槽不因后来勾完/改期而改快照。

### 9.2 每条样本

顺序：

1. 锁屏或暂停 → `Away`
2. 娱乐规则 → `Distraction`
3. 闲置 ≥ 180 秒 → `Away`
4. 前台是 GameLife → `Side`
5. 否则用 app / 标题 / URL / `document_path` 对快照标题 token（所有角色，不再只切主线标题）：
   - 命中同一角色（一条或多条）→ 主线 `CoreCandidate`，支线或长期规划 `Side`，杂项 `Admin`
   - 命中多种角色 → `Unsure`（槽末 AI 在这些 id 里选）
   - 命中零条 → `Unsure`（**不要**再走管理员名单 / 支线名单自动定性，也**不要**因工作路径变成 `CoreCandidate`）
（第 5 步之后若仍未定性，保持 `Unsure`。）

### 9.3 槽决策

跨度累加不变：8 分钟主线 + 7 分钟支线两段都进 `activity_seconds`，禁止 `dominant × 15`。槽的主判定跟占时最长的窗口走。

- 娱乐 / 离开占优：与现在相同，0 主线币。
- 对上主线的 `CoreCandidate` 跨度足够（沿用现有 13 分钟自动 Core 阈值，但只计**匹配主线**的样本，不再用落地路径 `grounded_strong_core`）：可自动 Core，不打 AI。
- 支线 / 杂项匹配占优：按现有 side / admin 占优规则结案，档次见下。
- 其余灰区：槽末文本 AI（有快照则选 `task_id` 或类别）→ 视觉 → 失败则 `pending_review`，不 `final`。

空任务板：全部非硬规则样本都是 `Unsure`，走 AI；不再 `empty_quests_work_path_still_auto_cores`。

### 9.4 发币档次

命中任务的列表角色（AI 选了某 `task_id` 则用该条角色；AI 只给了类别「主线」而没有 id，则按主线档）：

| role | 硬币 / 能量 | 8h、宝箱、连胜 |
| --- | --- | --- |
| mainline | 不打折 | 计入 |
| side、longterm | 6 折 | 不计入 |
| chore | 3 折 | 不计入 |

库内旧 `custom` 角色仍按支线 6 折。

## 11. 不做

- 全天、时区选择、准时以外的「到点再snooze」、每周选多个星期几、重复结束日期、提前展开整串。
- 子任务、标签云、智能清单。
- 用任务匹配压过娱乐 / 离开 / 锁屏。
- 多机合并任务表。
- FullCalendar、dnd-kit、Radix。
- 为自然语言解析打模型。
- 应用内音效、非任务类系统通知。

## 12. 测试

core：复选框不测；测 `repeat` 平移（含月末钳制、过期跳到 ≥ 今天）；清除时段把 `repeat` 打成 none；`match` 不看 `start`/`end`；多种角色 token 命中为 Unsure；娱乐仍压过主线标题；无快照时工作路径不再自动 Core；匹配主线 ≥ 13 分钟仍可自动 Core；拉边最短 900 秒。

前端：时刻 15 分钟步进；子菜单不把「移动到」摊成一长串；`dropRange` 仍 30 分钟；拉边与 `moveSameDay` 纯函数。`npx vitest run --dir src`。
