# GameLife：TickTick 清单内分组优先于整份清单

日期：2026-09-23  
状态：已确认，待实现  
范围：刷新清单后，设置页列出全部分组，清单可以展开到它下面的分组。分组和清单都能指定忽略、主线、支线、长期、杂项。分组的显式设置覆盖整份清单。产品仍是活动监测器。判定仍读本地未完成任务。

本文覆盖并取代 `2026-09-22-ticktick-task-sync-design.md` 里下面几处，其余仍以该文为准：

- 「分组只看清单角色下拉」。导入时先看任务所在分组，没有分组设置再看整份清单。
- 「`ticktick_column_roles` 继续不读不写」。分组角色写入 `config.json`。只保存用户明确选过的分组，不把缺省写成忽略。
- 刷新清单只拉 `GET /project`。刷新还要为每一份清单读 `GET /project/{id}/data`，从中取出分组。
- 授权范围只有 `tasks:write`。改为同时申请 `tasks:read` 与 `tasks:write`，否则新发出的令牌读不到清单。

## 1. 问题

现在一份清单只能整份归进一个预设分组。清单里面的分组（官方接口里的 column，列表视图也会返回）被丢掉。用户要把同一份清单里的不同分组分到主线、支线、长期或杂项，并让分组设置压过整份清单。

## 2. 成功标准

| 项 | 必须 |
| --- | --- |
| 展开 | 刷新成功后，设置页列出缓存里的全部分组。每个清单可展开。展开后按 `sortOrder` 升序、再按分组 id 字典序，列出分组名称和角色 |
| 空分组 | 一份清单没有分组时，展开后显示「这个清单没有分组，任务按整份清单归类。」 |
| 清单角色 | 仍是忽略、主线、支线、长期、杂项。新清单默认忽略 |
| 分组角色 | 选项是跟随清单、忽略、主线、支线、长期、杂项。跟随清单不落盘。其余四个角色和忽略才写入 `ticktickColumnRoles` |
| 优先级 | 任务有 `columnId`，且该分组 id 在 `ticktickColumnRoles` 里有合法角色：用分组角色。否则用整份清单的角色。任务没有 `columnId`，或清单没有分组：只用清单角色 |
| 忽略 | 最终角色是忽略，或清单未设置且分组也未设置：不导入。分组设为忽略时，即使清单是主线也不导入。清单是忽略、分组明确设为主线、支线、长期或杂项：导入该分组里的未完成任务 |
| 新分组 | 刷新见到的新分组不写入 `ticktickColumnRoles`，因此跟随清单，而不是默认忽略 |
| 拉取范围 | 清单角色不是忽略，或它缓存里的某个分组角色不是忽略：拉取该清单。只为了分组覆盖才去拉一份原本忽略的清单 |
| 已导入任务 | 下一次全量成功同步按新的最终角色改预设分组。最终角色变成忽略：删掉本机行，不删除 TickTick 上的任务，也不把本机未写回的修改推上去 |
| 写入目标 | 不变。新建任务仍写入该角色下 `sortOrder` 最小的清单，并列时清单 id 字典序较小。不根据分组选择清单，创建请求也不带 `columnId` |
| 刷新失败 | 某一份 `GET /project/{id}/data` 失败：保留该清单上次的分组缓存和它的分组角色。其他成功的清单照常更新。这一轮不删已导入任务，不前移 `ticktick_last_sync_at`。结果文案说明有清单没读到 |
| 权限 | `GET /project` 或项目数据返回权限不足：刷新失败，文案「TickTick 授权不足以读取清单，请重新连接。」不改清单缓存，不改两种角色映射，不删任务 |
| 打开设置 | 只读缓存，不打网络 |

明确不算本波的事：不按分组挑选写入清单；不把本机新建任务放进某个分组；不同步子任务、备注、重复规则；不用非官方接口。

## 3. 数据

`config.json`：

- `ticktickProjectRoles`：清单 id → `ignore` / `mainline` / `side` / `longterm` / `chore`。缺键的新清单在刷新时写成 `ignore`。
- `ticktickColumnRoles`：分组 id → 同上五个值。没有这把键，或键被删掉，表示跟随清单。不接受 `inherit` 这个存储值。界面上选「跟随清单」就是删掉这把键。

`app_meta['ticktick_projects_json']` 仍是刷新得到的项目数组。每个项目对象保留接口原有字段，并保证实现能读到：

- 项目 `id`、`name`、`sortOrder`、`viewMode`
- `columns`：`id`、`name`、`sortOrder`、`projectId`

旧缓存没有 `columns` 时，当成这份清单还没有分组，直到下一次成功的刷新。不要用任务标题猜分组。

分组角色的键是分组 id，不是「清单 id + 分组 id」。一份清单读成功后，缓存里已经不在的分组，从 `ticktickColumnRoles` 删掉。读失败的清单不动它名下的分组角色。`GET /project` 已不再返回的清单，从缓存和分组角色里去掉；这不是单份数据读取失败。

`user_version` 仍是 6。任务行不增加分组列。判定快照仍是 `id` / `title` / `role`。

## 4. 授权

连接时的 scope 为 `tasks:read tasks:write`（请求里按 OAuth 习惯编码空格）。只申请 `tasks:write` 时，新令牌会在 `GET /project` 上得到 `Insufficient scope`。

不读取、不迁移旧槽 `ticktick-access`。令牌仍只在 `secrets.json` 的 `ticktick_access_token` 与 `ticktick_refresh_token`。

已经连上、但现有令牌读清单权限不足的用户，需要再点一次「连接」。在此之前刷新失败，缓存保持原样。

## 5. 刷新与同步

刷新：

1. `GET /open/v1/project`。
2. 对返回的每一份清单 `GET /open/v1/project/{id}/data`。
3. 从 `columns` 读取分组。任务上的 `columnId` 只在同步归类时使用，刷新不必把任务存进缓存。
4. 新清单角色补成忽略。新分组不写角色。
5. 写回 `config.json` 与 `ticktick_projects_json`。失败的那一份清单沿用缓存里该 id 的旧对象；缓存里也没有时，设置页只显示项目列表接口给出的名称，分组为空，并带上失败文案。

同步仍走现有的每小时拉取和立即同步。差别只有两处：

- 除了角色不是忽略的清单，再额外拉取「缓存中存在非忽略分组角色」的清单。
- 对拉取到的每个未完成任务先算最终角色，再决定插入、改分组或从本机移除。`columnId` 不进入备注、重复或子任务。

全量成功的定义不变：这次决定要拉的每一份清单，以及完成列表，都成功。任一失败：不删除任何已链接任务（包括「最终角色变为忽略」的移除），不前移 `ticktick_last_sync_at`。成功清单上的标题和时段仍可按现有脏标记规则更新。

分组从一份成功读到的清单里消失，而任务还在且不再带这个 `columnId`：按整份清单的角色归类。任务 id 从所有成功拉取的未完成集合和完成列表里都消失：仍按 2026-09-22 的规则删除本机行。

创建请求不带 `columnId`。TickTick 可能把新任务放进默认分组。若该分组最终角色是忽略，下一次全量成功同步把本机行拿掉，远端任务保留。

## 6. 设置页

清单行保持现在的角色下拉，并增加展开。展开状态只留在页面里，不进 `config.json`。

分组下拉的「跟随清单」是未保存状态。选中忽略或四个预设角色时立刻 `saveSettings`。改回「跟随清单」时删掉对应键再保存。

文案：

- 空分组：「这个清单没有分组，任务按整份清单归类。」
- 权限不足：「TickTick 授权不足以读取清单，请重新连接。」
- 部分清单没读到：「有清单没能刷新，这些清单仍显示上次的分组。」

不写 hex。页面仍只经 `src/lib/api.ts` 调用 `invoke()`。

## 7. 测试

`gamelife-core` 纯函数：

- 分组角色覆盖清单角色，包括分组忽略、清单为主线。
- 没有分组角色时跟随清单。新分组不能被当成忽略，除非清单本身是忽略。
- 清单忽略且分组明确为主线时，任务进入 `list-mainline`。
- 没有 `columnId` 时只用清单角色。
- `write_target` 不读分组角色。

`gamelife`：

- 项目数据里的 `columns` 能解析出 id、名称、`sortOrder`。任务解析保留 `columnId`。
- 一份项目数据失败时，不删除已链接任务，不前移 `ticktick_last_sync_at`，该清单的旧分组缓存还在。
- 全量成功后，最终角色为忽略的已链接任务从本机删除，推送动作里没有对它的远端删除。
- 授权 URL 含 `tasks:read` 与 `tasks:write`。

前端：

- 分组未出现在 `ticktickColumnRoles` 时，下拉是跟随清单。
- 空的 `columns` 得到空分组文案。

## 8. 不变量

总开关默认关闭。关闭时不拉取、不写回。只导入未完成任务。子任务、备注、重复规则不同步。判定不读 TickTick，不读 `ticktick_cache`。打开设置不打网络。令牌不进 `config.json`，不回传给页面。官方主机仍是 `https://api.ticktick.com/open/v1`。同步不发币，不改已结束的槽。
