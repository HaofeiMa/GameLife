# GameLife：灰区 AI 必须点中一条任务

日期：2026-09-29  
状态：已确认，待实现  
范围：灰区的文本判断和截图判断使用同一份材料、同一种回复。材料是未完成任务、类别说明和应用名单。回复必须点中一条任务。点不中则待复核。产品仍是活动监测器。硬规则和元数据自动结案仍在 AI 之前。

本文覆盖并取代下面几处，其余仍以上游规格为准：

- `2026-09-15-tasks-interaction-design.md` §9.3「有快照则选 `task_id` 或类别」。有未完成任务时只接受 `task_id`。
- 同节「空任务板走 AI」。钉住的未完成任务为空时，不调用文本，也不调用截图，灰区直接 `pending_review`。
- 同文 §9.4「AI 只给了类别、没有 id，则按主线档」。没有 `task_id` 的回复不结案。
- `2026-09-13-activity-monitor-design.md` §5.3 快照为空时的类别 JSON，以及其中 `research_support` 由文本结成辅助。生产槽末不再走这条分支。
- 同文里截图以自由类别结案（含把未定时间收成辅助）。截图回复改为 `task_id`，结案函数与文本相同。

不改：硬规则顺序、娱乐名单的硬匹配、闲置离开、元数据自动结案阈值、任务标题的本地匹配、提示最多 20 条任务的挑选顺序、发币折扣、人工改判、受保护窗口禁止上传。

## 1. 问题

类别说明和应用名单已经出现在文本提示末尾，但有未完成任务时程序只接受 `task_id`。模型按「聊天工具」答成杂项会被丢掉。截图提示没有类别说明，也没有应用名单，并且可以不点名任务就把槽记成辅助、杂项或娱乐。

用户要求：两类 AI 都看到任务、类别说明和应用名单；这两类说明只帮助从任务里挑选；必须点中一条任务，否则待复核。

## 2. 成功标准

| 项 | 必须 |
| --- | --- |
| 调用时机 | 硬规则和元数据已经能结案的槽不调用 AI |
| 空任务 | 该槽钉住的未完成任务为空：不构建、不发送文本提示，也不发送截图请求。灰区为 `pending_review`，主线 / 支线 / 杂项发币为 0 |
| 文本材料 | 有任务且窗口摘要非空：提示含任务、非空类别说明、非空应用名单、窗口摘要，并写明说明和名单只是挑选证据 |
| 文本回复 | 只接受 `{"task_id": string\|null, "confidence": number}`。点中则按该任务角色结案，不再调用截图 |
| 截图材料 | 文本未点中，且存在可上传的截图：提示含同一份任务、说明和名单，并保留现有画面上下文。图像单独附上。提示不再要求 `category` 或 `reason` |
| 截图回复 | 与文本同一 JSON、同一解析、同一结案函数。点中时 `used_vision = 1` |
| 未点中 | `null`、置信度低于 0.7、id 不在本次提示的任务里、JSON 不合法、超时、无密钥、接口失败：该步不结案 |
| 无截图 | 没有截图、截图被跳过或错过、或截图受保护不能上传：文本未点中则 `pending_review` |
| 活动明细 | 点中主线、支线（含长期规划、自定义）、杂项时，有效秒数写入对应活动桶，与槽类别一致 |
| 旧槽 | 已经 `final` / `unknown` / `pending_review` 的槽不重算。尚未写出状态的槽，在新程序下一次槽末结算时走本文 |
| 设置文案 | 「关于」里的判定顺序与本文一致。类别说明的空值说明改为：空着不进提示 |

明确不算本波的事：不把杂项名单、支线名单或主线应用改回硬规则；不重算已结案槽；不从界面去掉历史「辅助」；不改变 0.7 门槛、20 条上限和发币折扣；不改人工改判。

## 3. 槽末顺序

以下各项在任何 AI 调用之前完成，行为不变：

1. 锁屏或暂停 → 离开。
2. 娱乐名单命中 → 娱乐。
3. 闲置满 180 秒 → 离开。
4. 前台是 GameLife → 支线。
5. 未完成任务标题对上窗口：同一角色为该角色，多种角色为未定，零条为未定。杂项名单和支线名单不在这一步定性。

元数据能定案时也不调用 AI：整段未观测；离开满 600 秒且匹配主线不足 300 秒；匹配主线满 780 秒且支线 + 杂项 + 娱乐不超过 60 秒；支线 + 杂项 + 娱乐满 300 秒且压过匹配主线。

剩下的是灰区。先用 `judge_slot` 且不传入截图结果，得到待复核的底稿。然后：

1. 未完成任务为空：保持底稿。
2. 窗口摘要为空：跳过文本。摘要非空则发送文本。点中则替换底稿并结束，不调用截图。
3. 仍待复核，且有未完成任务、有可上传截图：发送截图。点中则替换底稿，`used_vision = 1`。
4. 否则保持待复核。受保护的历史样本仍从文本摘要中去掉，但不因此禁止一张未受保护的截图。受保护的截图本身仍禁止整段上传。

## 4. 提示与回复

文本和截图共用这一段说明（中英以实现里的现有提示语言为准，语义如下）：

> 在未完成任务里最多选一条。类别说明和应用名单只作为「这段窗口更像哪条任务」的证据，不是要返回的类别。没有一条适合时 `task_id` 为 null。只回复 JSON `{"task_id": string|null, "confidence": number}`。

正文顺序：

1. 任务：`id`、`title`、`role`。最多 20 条。挑选顺序不变：先放窗口摘要里对得上标题的，再补主线，再按原有排序补齐。本地匹配仍使用钉住的全集，不受 20 条限制。
2. 类别说明：只写非空段，键为 `mainline`、`side`、`admin`、`entertainment`。
3. 应用名单：主线应用、支线、杂项、娱乐。某一份为空则整行不写。每份仍最多 20 个名字。
4. 窗口：`app`、`title`、`url`、`document_path`、`idle`。受保护样本不出现。

截图提示在此之后保留现有画面上下文：各窗口占用的时间、提示秒数、这一帧的应用、标题、网址、文档路径。不再写「Today's main quests」，也不再列举 `core_research` 等自由类别。旧的类别 JSON 解析不再用于槽末。

两边都用 `parse_task_match_json` 和 `apply_task_match`。置信度门槛仍是 0.7。解析对照的是这次放进提示的那至多 20 条，不是钉住的全集；模型报出提示里没有的 id，视为未知任务，不结案。

## 5. 点中与失败

有效秒数仍是已观测秒数减去离开和娱乐。点中后：

| 角色 | 槽类别 | 写入 | 发币 |
| --- | --- | --- | --- |
| 主线 | 主线 | `credited_core_seconds` 与 `activity.core` | 原额，计入 8 小时。规则与现有 `apply_task_match` 相同 |
| 支线、长期规划、自定义 | 支线 | `credited_side_seconds` 与 `activity.side` | 现有支线折扣，不计入 8 小时 |
| 杂项 | 杂项 | `credited_chore_seconds` 与 `activity.admin` | 现有杂项折扣，不计入 8 小时 |

有效秒数为 0 时仍按该角色结案，发币为 0。文本点中时 `used_vision` 为 0。

未点中时不改底稿：`pending_review`，三类发币为 0，不猜测类别。槽末不得把截图的类别结果送进 `judge_slot` 来改写辅助、杂项或主线。`judge_slot` 内部原有的视觉类别分支可以留在函数里，但生产槽末调用它时 `vision` 为 `None`。

`finalize_slot_end` 见到 `pending_review` 时直接返回，与 `final` / `unknown` 相同。启动时只补状态仍为空、且已经结束的槽。已经写成待复核的槽不重新调用 AI。

人工把待复核改成某一类的入口不变。

设置页「判定顺序」改为：

1. 硬规则：锁屏或暂停 → 离开；娱乐名单 → 娱乐；闲置满 3 分钟 → 离开；GameLife → 支线；未完成任务的标题对上 → 按该任务的角色。对不上 → 待定。杂项名单和支线名单不在这一步定性。
2. 元数据够确定就直接结算，不调 AI：匹配到的主线满 13 分钟，且支线、杂项、娱乐合计不超过 1 分钟 → 主线；这三类合计满 5 分钟且压过主线 → 归到占优的一类；离开满 10 分钟且匹配主线不足 5 分钟 → 离开。
3. 剩下的是灰区。这一槽没有未完成任务 → 待复核，不调用 AI。有任务则文本判断必须从这些任务里点一条，置信度至少 0.7。类别说明和应用名单只帮助挑选。
4. 文本没点中，且这一槽有可用截图：截图判断用同一份材料和同一条回复规则再点一次。点中按该任务的角色结案。没有截图、截图受保护、没点中或回复不合法 → 待复核，不猜类别。

类别说明一节的说明改为：「灰字为样稿。空着保存不进提示。写了也只在灰区帮助 AI 从任务里挑选，不直接定类别。」

已经显示在时间轴上的辅助来自旧槽，保留 `research_support` 的展示。新的槽末结算不再产生辅助。

## 7. 测试

- 有任务的文本提示包含任务、非空类别说明、非空名单，并要求 `task_id`。空的名单行不出现。超过 20 条时提示里仍不超过 20 条。
- 截图提示包含同样三段和画面上下文，且不要求返回 `category`。
- 点中主线、支线、杂项时，槽类别、发币字段和活动明细一致。置信度低于 0.7、`null`、未知 id、类别 JSON 都不结案。
- 没有未完成任务的灰区不发 AI，结果是待复核。
- 文本没点中、截图点中时 `used_vision` 为 1。没有截图或截图受保护时保持待复核。
- 已有的硬规则和元数据自动结案测试继续通过。
